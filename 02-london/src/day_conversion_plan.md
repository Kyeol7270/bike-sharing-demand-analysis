# 런던 데이터 시간별 → 일별 변환 계획서

## 0. 원칙

- **원본 파일(`02-london/data/london_merged.csv`)은 절대 수정하지 않는다.** 읽기 전용으로만
  사용한다.
- 변환 결과는 **새 파일**로 `02-london/data/day.csv`에 저장한다(원본과 별도 파일, 덮어쓰기 아님).
- 집계 규칙의 기본 근거는 `01-washington/docs/HOUR_TO_DAY_AGGREGATION_RULES.md`이며, 이번 계획서는
  그 규칙을 런던 데이터에 맞게 구체화·보완한 것이다. 런던용 비교 대상 day.csv가 없으므로 결과는
  "검증됨"이 아니라 "규칙을 적용한 것"임을 명시한다(원 규칙서 6절 단서와 동일).

## 1. 원본 컬럼

`timestamp, cnt, t1, t2, hum, wind_speed, weather_code, is_holiday, is_weekend, season`
(17,414행, 결측치 0건, 기간 2015-01-04 ~ 2017-01-03, 시간 단위)

## 2. 컬럼별 변환 규칙

| 결과 컬럼 | 규칙 | 근거/비고 |
|---|---|---|
| `instant` | 1부터 순번 재부여 | 원본 인덱스와 무관, 새로 생성 |
| `year` | `timestamp`에서 연도 추출 (2015/2016/2017 그대로) | 상대 인코딩(0/1/2) 아님 — 사용자 지시대로 실제 연도 값 사용 |
| `month` | `timestamp`에서 월 추출 (1~12) | 사용자 지시 |
| `day` | `timestamp`에서 일 추출 (1~31) | 사용자 지시 |
| `weekday` | `timestamp`의 날짜에서 요일 이름 추출 (`Monday`, `Tuesday`, ... `Sunday`) | 숫자 인코딩(0=일요일 vs 0=월요일) 컨벤션 혼동을 피하기 위해 요일 이름 문자열로 저장 |
| `season` | 하루 내내 동일한 원본 값을 그대로 사용 (0~3, 재코딩 없음) | 사전 검증: 730일 전부 하루 내 불일치 0건. 값 의미(0=봄·1=여름·2=가을·3=겨울)는 참고만 하고 **값 자체는 원본 그대로 사용** |
| `is_holiday` | 하루 내내 동일한 원본 값을 그대로 사용 (0/1) | 사전 검증: 730일 전부 불일치 0건 |
| `is_weekend` | 하루 내내 동일한 원본 값을 그대로 사용 (0/1) | 사전 검증: 730일 전부 불일치 0건 |
| `working` | 파생 컬럼: `is_holiday==0 and is_weekend==0`이면 1, 아니면 0 | 사용자 지시("주말도 휴일도 아닌 날은 working=1") — 런던 원본에는 없던 컬럼이라 이 정의로 새로 만듦 |
| `weather_code` | 원본 코드 값 그대로 사용(재정의·재매핑 없음), 다음 3단계 규칙으로 하루 대표값 결정 | 사용자 지시("weather_code 원본 기준 그대로 활용") + 워싱턴 weathersit 전용 규칙(2절) 그대로 적용 |
| `t1`, `t2`, `hum`, `wind_speed` | 하루 내 존재하는 시간 레코드의 평균(mean), 소수 1자리 반올림 | 런던 원본이 소수 1자리 형식이라 그 자릿수를 그대로 유지(규칙서 3절 원칙) |
| `cnt` | 하루 내 존재하는 시간 레코드의 합계(sum) | 규칙서 그대로, 정수라 반올림 불필요 |
| `n_hours_observed` | 그날 실제로 기록된 시간 레코드 수 (0~24) | 사용자 지시("하루에 몇 시간이 기록됐는지 컬럼으로 남길 것") |

`weather_code`의 3단계 규칙 (워싱턴 규칙서 2절과 동일한 순서):
1. 그날 등장한 등급 중 **가장 나쁜(숫자가 큰) 등급이 연속 4시간 이상 지속**되면 그 값을 채택.
   (연속 4시간은 `timestamp`의 시(hour) 값이 끊기지 않고 이어진 구간을 의미 — 결측 시간이 있으면
   그 지점에서 streak이 끊긴 것으로 처리)
2. 1을 만족하는 등급이 없으면 **최빈값**을 채택.
3. 최빈값이 동률이면 **더 나쁜(숫자가 큰) 등급을 우선** 채택.

## 3. 이번 변환에서 만들지 않는 컬럼

| 컬럼 | 이유 |
|---|---|
| `casual`, `registered` | 런던 원본에 대여자 유형 구분 데이터 자체가 없음(`cnt` 총합만 존재) — 생성 불가. 워싱턴과 스키마를 맞추기 위해 빈 값(NaN) 컬럼으로라도 만드는 방안도 검토했으나, 실제 값 없이 자리만 만들면 결측치 처리 혼동만 커진다고 판단해 만들지 않기로 확정 |

## 4. 결측 시간 처리

- 원본 730일 중 **34일에서 총 106시간이 결측**(24시간 미만 기록)됐음을 사전 확인함.
  최악 사례: 2016-06-24 (9시간만 기록).
- 규칙서 4절 원칙대로 **결측 시간은 채우지 않고, 그날 실제로 존재하는 레코드만으로 평균·합계를
  계산**한다.
- `n_hours_observed` 컬럼으로 이 사실을 결과 파일에 남겨, 관측치가 적은 날(대표성이 낮은 날)을
  분석 단계에서 식별·필터링할 수 있게 한다.

## 5. 사전 검증 완료 사항

- `season`, `is_holiday`, `is_weekend`: 730일 전부 하루 내 동일값 (불일치 0건) — groupby(date).nunique()로 확인.
- `weather_code` 값 순서(1<2<3<4<7<10<26)가 실제 기온·습도 패턴(숫자가 클수록 기온↓·습도↑ 경향)과
  대체로 일치함을 확인 — "숫자가 클수록 나쁜 등급" 전제가 워싱턴과 마찬가지로 성립.
  단, 코드 10(뇌우)은 데이터에서 표본이 14건뿐이라 결과를 육안으로 한 번 더 확인 권장.
